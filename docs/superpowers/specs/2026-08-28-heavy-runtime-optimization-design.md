# Heavy Runtime Optimization Design

## 目的

実行負荷が高い数学関数を、既存の公開 API、エラー条件、入力保持、および README に記載された誤差保証を維持したまま軽量化する。結果の最下位ビットと内部の中間値は変化してよい。データパック容量とリロード時間の小幅な増加は許容するが、実行時の改善が小さい変更のために大幅な容量増加は行わない。

対象は `tan`、`tan_degrees`、`log`、`reciprocal`、`divide`、`square_root`、`bezier`、`remainder`、`modulo`、`power` と、それらが利用する周期縮約・正規化・逆数計算である。すでに軽量化した `exp` と `reciprocal` の現行実装を基準にし、改善を後退させない。

## 維持する契約

- 成功時は `error` を消去し、float の `ans` を設定して function result `1` を返す。
- 失敗時は `ans` を消去し、既存のエラー ID を設定して function result `0` を返す。
- 公開入力は変更しない。
- `reciprocal`、`divide`、`square_root`、`log`、`exp`、`power`、三角関数について README 記載の誤差上限を維持する。
- `divide` のサブノーマル結果は既存の最小サブノーマル単位の保証を維持する。
- `remainder` と `modulo` は近似へ変更せず、binary32 の有限入力に対する既存の完全一致を維持する。
- `tan` の cos がゼロに近い場合の保守的な拒否条件を維持する。
- `bezier` は解を含むパラメータ区間の幅を最終的に `2^-20` 以下にする。
- NaN、無限大、ゼロ、符号、定義域、オーバーフローおよびアンダーフローの分類を変更しない。

## 採用方式

共通処理を高速化し、関数固有の核は段階計算と適応的な反復回数で軽くするハイブリッド方式を採用する。

全面的な lookup table 化は実行速度が最も高い可能性があるが、生成物が大きくなり、リロードと保守の負担が増えるため採用しない。全面的な低次数近似は小型で高速だが、境界域の既存保証を維持しにくいため採用しない。lookup は指数分類など、入力範囲が有限で共有効果の高い箇所に限定する。

## 共通 binary32 正規化

`log`、`reciprocal`、`divide`、`square_root` に重複している、値を2倍または半分にしながら仮数範囲へ移す再帰処理を共通化する。

共通正規化器は有限の非ゼロ絶対値を入力とし、次を scratch storage に出力する。

- 所定範囲へ収めた仮数
- 2の指数
- サブノーマルまたは通常値の分類
- 後続処理が必要とするスケール係数

指数判定には、線形探索ではなく範囲ガード付きの平衡分岐を使用する。分岐で指数帯を決めた後、少数のスケール演算だけで仮数を得る。単一の巨大 JSON に集中させず、生成器が複数の決定木へ分割する。これにより、最悪経路を入力の指数差に比例する再帰から、固定段数の比較へ変更する。

呼び出し元固有の入力検証、符号処理、結果の丸め、オーバーフローおよびアンダーフロー処理は各公開関数に残す。共通正規化器は公開 API を持たず、`ans` や `error` を確定しない。

## 関数群ごとの変更

### tan と tan_degrees

現在重複している周期縮約を1回だけ行い、同じ正規化済み位相から sin と cos の多項式を評価する。sin と cos を別々の公開経路として呼び直さない。cos の近似値と既存のガード判定を用いて定義不能域を判定し、その後に共通逆数核で除算する。

単独の `sin`、`cos`、`sin_degrees`、`cos_degrees` の契約は変更しない。角度保証範囲外の挙動も、既存の有限入力受付方針と保守的ガードを維持する。

### log と divide

`log` 専用の入れ子になった Newton 逆数式を、score/storage に中間値を保存する段階計算へ変更する。各段階の式木を小さくし、同じ部分式を再評価しない。多項式の次数と range reduction は、精度試験で削減可能と証明できない限り維持する。

`divide` では正規化済み除数の逆数、積の high/low、残差、補正済み商を順に保存する。現行の high/low 補正とサブノーマル処理を維持し、式木の重複だけを除く。共通正規化器を利用して、正規化の再帰呼び出しを削減する。

### square_root

共通正規化器で入力を適切な仮数域へ移し、指数の偶奇を一度分類してから Newton 法を実行する。通常域は少ない反復回数を使用し、境界域または残差が大きい入力だけ追加反復する。

反復削減は推測で行わない。最大有限値、最小通常値、サブノーマル、2の冪の両隣、および無作為な binary32 値で既存の相対誤差保証を満たす場合だけ採用する。満たさない範囲は現行反復数へフォールバックする。

### bezier

単調な x 曲線に対して、常に解を含む `[lo, hi]` を保持する safeguarded Newton 法へ変更する。Newton 候補が区間外、有限でない、または微分が小さすぎる場合は、その反復だけ二分法を使う。候補を評価した後は符号に従って必ず bracket を狭める。

Newton により近似値が早く収束しても、終了時の bracket 幅が `2^-20` 以下であることを確認する。不足分は二分法で補う。通常曲線の平均負荷を下げ、平坦または悪条件の曲線では現行の20回二分法相当へ安全にフォールバックする。制御点検証と端点処理は維持する。

### remainder と modulo

公開結果は厳密な二進縮約のままとする。最上位の減算位置を共通指数分類器で決め、各ビット位置を下りながら条件付き減算する。指数位置へ到達するまで1段ずつ倍率を変更する上昇再帰を廃止し、開始位置を直接選ぶ。

`modulo` は `remainder` と同じ縮約結果を使用し、必要な負数補正だけを後段で行う。除数が大きい場合、等しい場合、符号が異なる場合、最小サブノーマルを含む場合の既存結果を維持する。

### power

通常経路は軽量化後の `log` と `exp` を使用する。整数判定、符号、ゼロ、非有限値の早期分岐を先に行い、境界分類が不要な入力では高精度分類器を実行しない。

オーバーフロー境界経路では、high/low の積、正規化値、多項式の各段を一度だけ計算して保存し、predicate 間での部分式再評価をなくす。境界分類器の次数削減は、既存の境界テスト全件と追加の隣接 binary32 値で誤分類がなく、相対誤差 `5e-5` を維持できる場合だけ採用する。

## 実施順序

変更は次の単位で順に行う。各単位を生成・検証してから次へ進み、障害があればその単位だけを戻せる構造にする。

1. `tan` / `tan_degrees` の周期縮約共有
2. 共通 binary32 正規化器と既存利用箇所の移行
3. `log` 専用逆数と `divide` の段階計算
4. `square_root` の適応的反復
5. `bezier` の safeguarded Newton 法
6. `remainder` / `modulo` の直接開始型縮約
7. `power` の通常経路早期分岐と境界分類器整理

`exp` と現行の共通 `reciprocal` は、利用側の変更に必要な場合を除いて再設計しない。

## 実行負荷の測定

Minecraft 内の実時間は環境差が大きいため、決定的な静的指標と数値試験を主な合格判定にする。

- 展開された number provider の式ノード数
- 1回の公開呼び出しで通過し得る mcfunction command 数
- predicate / range 判定の最大数
- 再帰深度および反復回数
- 生成物のファイル数と総 byte 数

各対象について変更前の基準値をテストまたは測定スクリプトへ記録する。変更後は平均想定経路だけでなく最悪経路も基準値未満にする。ただし悪条件時の安全フォールバックを持つ `bezier` と `square_root` は、最悪経路が同等でも通常経路が明確に減少し、他の指標が悪化しない場合を許容する。

容量増加には一律の絶対上限を先に置かず、各段階で runtime 削減量と比較する。共有されない大規模 table、到達頻度の低い経路だけを高速化する大規模 table、または実行負荷テストで差が出ない生成物は採用しない。

## テスト

実装は各段階で、最初に変更対象の負荷上限または数値境界を表す失敗テストを追加してから行う。

- 既存の全テストを維持する。
- generator の `--check` を通し、manifest と生成物の一致を確認する。
- 公開 API の storage、function result、エラー ID、入力保持を検証する。
- 正常値、符号付きゼロ、最大有限値、最小通常値、サブノーマル、2の冪とその隣接値を検証する。
- 超越関数は決定的 seed の無作為試験と、既知の悪条件・境界値を検証する。
- `remainder` と `modulo` は参照 binary32 演算とのビット一致を検証する。
- `bezier` は平坦な微分、端点、対称曲線、強く偏った曲線で bracket 不変条件と最終幅を検証する。
- `power` と `divide` はオーバーフロー、アンダーフロー、サブノーマル境界の隣接値を重点的に検証する。
- 静的負荷テストで式ノード、command 数、判定数、再帰深度の上限を固定する。
- 最終的に `node --test` と `node tools/generate-math-providers.mjs --check` を実行する。利用可能なローカル環境があれば Minecraft Snapshot 10 の統合テストも実行する。

数値保証を満たさない軽量化は反復数や多項式次数を元へ戻す。保証を維持できても静的負荷が改善しない変更は採用しない。

## 生成器とファイル管理

生成対象は `tools/generate-math-providers.mjs` で一元管理し、手書きの生成済み JSON や mcfunction を増やさない。新しい provider、predicate、内部 function は `tools/generated-math-files.json` に決定的な順序で記録する。廃止した生成物は旧 manifest との差分として削除し、旧経路と新経路を二重に残さない。

scratch storage 名は用途が分かる固有名にし、公開入力や別の計算核が生存中に使う値を上書きしない。共通核の入力・出力・破壊する scratch 項目は生成器内で隣接して定義し、呼び出し元との暗黙依存を避ける。

## 非対象

- README の公開関数追加・削除
- function tag や公開 storage schema の変更
- 誤差保証の緩和
- `remainder` / `modulo` の近似化
- 実行時改善を伴わない全面的なファイル再配置
- lookup table の無制限な大型化
- 今回の目的と無関係な既存の未コミット変更
